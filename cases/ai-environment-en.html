AI Design Environment

Not prompts, but a working system. I built an environment on Claude Code where every task is run by an agent with its own rulebook: it builds a screen on the design system kit or a layout in Figma, checks its own work, and only then hands over the result.

Approach

AI without rules produces a screen that is correct but bland. Rules remove the bad but don’t make the screen any stronger, and the typical AI tells show at once: indigo accents, emoji instead of icons, sterile data. So I don’t write prompts for each task: knowledge lives in rulebooks, and the work is done by agents that read them.

How a task moves through the environment

  1. 01
    The rulebook is read before work starts
    Each area has its own: realism, spacing on a 4/8 grid, anti-slop, 39 rules for AI interfaces, rules for flows in Figma.
  2. 02
    Three approaches, then a choice
    Before building an interface element, the agent presents three working solutions from the reference library, names the trade-off of each and explains its choice.
  3. 03
    Built from real components
    A prototype is built on the design system kit in Storybook and a Figma layout from library instances, not from drawn lookalike blocks.
  4. 04
    Self-check before saying “done”
    Render and screenshot, spacing audit, de-slop, overlap detector in Figma. A successful tool response doesn’t yet mean the intended result was achieved.

Agents by area

Areas differ only in their rulebook and how they self-check. The route is the same for all: read the rulebook, build, check the work, file the result by the rule.

Rulebooks and skills

A rulebook is a file of rules; a skill loads it by name. My eight own skills are called directly, while external packs sit behind four group routers so they don’t clutter the choice. A new skill is added only through an onboarding protocol, never dropped into the folder as is.

Design system and kit

One design system, two build paths. A Figma layout is assembled from component instances using the library index; an HTML prototype is built on the kit with real React components, tokens, fonts and icons from the set. Agents don’t recreate component markup by hand: it drifts from the kit with the very first update.

Reference library

1042 techniques from 930 live screens, each with a recorded boundary: when the technique doesn’t work. On top of the library sits a repertoire of 64 approaches to 11 interface elements: list row, object header, filter panel, empty state and others. The library answers how a detail is done in real products; the repertoire answers which ways there are to build an element at all.

Design pipeline

Brief, JTBD, story map, OOUX and user flows. The agent guides you through the stages, asks questions in plain language and draws the artifacts on a FigJam board. The pipeline helped the bank’s teams produce artifacts without design experience; more on this in the Service E case study.
